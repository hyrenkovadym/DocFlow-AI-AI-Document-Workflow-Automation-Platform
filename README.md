# DocFlow AI

**AI-powered document intake and workflow automation platform**

DocFlow AI is a production-style full-stack portfolio project for internal business document operations.

## Current phase
Phase 4 hardening is implemented:
- backend workflow remains synchronous (no Celery runtime path yet),
- permissions and edge cases are covered with tests,
- frontend handles common API errors (`401`, `403`, `409`) more clearly.

## Tech stack
- Backend: FastAPI, SQLAlchemy 2.x, Alembic, PostgreSQL, Pydantic
- Frontend: Next.js (App Router), React, TypeScript, Tailwind CSS
- Tooling: pytest, ruff, Docker Compose, GitHub Actions

## Core features
- JWT auth + RBAC (`admin`, `reviewer`, `user`)
- File upload (`txt`, `pdf`, `docx`) with validation
- Mock AI provider for classification and structured extraction
- Human-in-the-loop review queue with approve/reject and field patching
- Audit logs for document lifecycle events
- JSON/CSV export from approved/exported records
- Reprocess endpoint for iterative correction/demo reliability

## Permissions (MVP)
- `user`:
  - can upload documents,
  - can list/view/export/reprocess only own documents,
  - cannot access review queue,
  - cannot approve/reject,
  - cannot access audit logs.
- `reviewer`:
  - can access review queue,
  - can approve/reject and patch extraction fields,
  - can access documents for review and export as allowed by current design,
  - cannot access audit logs.
- `admin`:
  - full reviewer capabilities,
  - can access audit logs.

## Export behavior (Phase 4)
- Export endpoint allows documents in status `approved` or `exported`.
- Re-export is supported.
- Every export request creates a new `ExportRecord` and `document_exported` audit event.
- Documents in other statuses return `409`.

## Reprocess behavior (Phase 4)
`POST /api/documents/{id}/reprocess`
- Allowed for owner, reviewer, admin.
- Forbidden for regular users on someone else’s document.
- Anonymous requests are rejected.
- Reprocess runs full sync pipeline again and updates extraction data.
- For `failed`, `approved`, and `exported` documents, reprocess is allowed and document returns to `needs_review`.

## Local setup
### 1. Clone and configure
```bash
git clone <repo-url>
cd docflow-ai
cp .env.example .env
```

### 2. Start PostgreSQL and Redis
```bash
docker compose -f infra/docker-compose.yml up -d postgres redis
```

### 3. Run backend
```bash
cd apps/api
pip install -e .[dev]
alembic upgrade head
python -m app.scripts.seed
uvicorn app.main:app --reload --port 8000
```

### 4. Run frontend
```bash
cd apps/web
cp .env.example .env.local
npm install
npm run dev
```

## Manual QA checklist
1. Register/login from UI.
2. Upload valid TXT/PDF/DOCX file and confirm status becomes `needs_review`.
3. Verify empty/unsupported/oversized upload errors are shown clearly.
4. Open `/reviews` as reviewer, patch fields, approve/reject.
5. Export approved document, then export same document again.
6. Reprocess an exported document and verify it returns to `needs_review`.
7. Confirm regular user cannot access review queue or audit logs.
8. Confirm admin can view audit logs.

## Security notes
- No real secrets committed.
- Mock AI is default; no external AI calls required for tests/demo.
- JWT-based protected API access.
- Upload file type and size validation enforced by backend config.

## Current limitations
- Synchronous processing only (async worker not active yet).
- OCR for images is not implemented.
- No bulk export endpoint yet.
- No multi-tenant organization boundaries yet.
